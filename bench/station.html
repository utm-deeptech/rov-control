Black Pill · state

Control loop timing

One loop every 1 ms (DMA moves the UART bytes, no RTOS). PID + mixer run every 10 ms. CPU load is the share of each second spent working; the rest it sleeps (WFI).

Signal path · what happens to your stick, every 10 ms on the Black Pill

① Pilot input topside

Sticks after deadzone, expo and pilot gain. Sent as PILOT 50×/s.

➜

② Holds (PID) board

Stick released → the hold locks the current value and the PID takes over that axis. Stick moved → you fly it, target follows.

➜

③ Demand into mixer board

Pilot + PID outputs per axis (surge … yaw).

➜

④ Thrusters board → ESC

Mixer → slew limit → reverse → output pin. 1100–1900 µs, 1500 = stop.

Type a value, press Enter: it is live immediately. Save to flash keeps it after a power cycle (disarmed only). Gains can be tuned while armed; wiring and the matrix only while disarmed.

Who does what

Topside (laptop app)

  • reads PS4 / PS3 / RC controller
  • deadzone, expo, pilot gain
  • buttons → requests: arm, mode, lights, tilt
  • video, logging, parameter editor

Pi (bridge)

  • UDP ⇄ UART, byte for byte
  • camera stream
  • no control logic: if it hangs, the board's failsafe still works

Black Pill (vehicle)

  • arming, failsafe (link lost → stop)
  • modes + PID holds (depth, heading, level)
  • thruster mixing, limit, slew, reverse, pin map
  • PWM: 6 ESCs, lights, camera tilt
  • parameters in flash
